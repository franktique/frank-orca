# Quickstart & Validation: API Client Tab

How to prove the feature works end to end. Contracts: [ipc-renderer-main](./contracts/ipc-renderer-main.md), [cli-rpc](./contracts/cli-rpc.md), [storage-format](./contracts/storage-format.md), [script-sandbox-api](./contracts/script-sandbox-api.md). Entities: [data-model.md](./data-model.md).

## Prerequisites

- Node 24, `pnpm install` (adds `quickjs-emscripten`, `chai`).
- Fixtures (committed under `src/shared/api-client/__fixtures__/`): `smoke.postman_collection.json` (2 top-level folders, nested G1–G10 groups, 37 requests each with a test script, `{{baseUrl}}`/`{{tenantId}}` headers, raw JSON bodies) and `smoke.postman_environment.json` (27 variables, ≥ 2 secret). Synthetic data mirroring the user's sample shape — no real tokens.
- A local echo/test server for scenarios: the e2e suite starts one with `node:http` on a random port; set `baseUrl` to it.

## Automated checks

```bash
pnpm tc
pnpm test src/shared/api-client src/main/api-client src/renderer/src/components/api-client
pnpm run check:code-quality:changed
oxlint
ORCA_BACKGROUND_LAUNCH=1 pnpm exec playwright test tests/e2e/api-client   # hidden window, CDP screenshots
```

Expected: all green. Unit suites must include the import round-trip (SC-001/SC-007), variable resolution, storage tombstone/GC, secret encryption with a fake `SecretStore`, sandbox `pm` API, and runner sequencing/stop/variable propagation.
